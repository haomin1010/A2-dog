## I1 ⚠ 转向过转：指令 90°，实际约 270°（左右都会）— 未解决

**发现**：2026-11-20 阶段 1 真机测试，`向左转九十度` / `向右转九十度` 实际转了约 270°。
**状态**：原因未确认。**在解决前不要测试转向**（前进/后退不依赖朝向，可以测）。

### 背景
- `turn` 是闭环：每 0.1s 读一次 yaw，累加已转角度，转够就停；读不到变化时会一直转到超时。
  超时 = 预计时间 × 2 + 3s，90° @ 0.6 rad/s ≈ 8.2s ≈ 280° —— **与现象吻合**，说明程序很可能一直以为"没转"。
- 已知：A2 的 `imu_state.rpy` 恒为 0（真机只读采样确认）。已改为由 `imu_state.quaternion [w,x,y,z]` 计算 yaw（提交 87c83b9），
  静止读数从 0.0 变为 0.031 rad，公式用标准四元数验证正确。

### 可能原因（待排查）
1. **测试时 PC2 上跑的仍是修复前启动的 body 进程**（最可能）。
2. 四元数在原地旋转时不更新（只反映倾斜）。
3. 左转时 yaw 实际减小（符号与代码假设相反）。
4. 四元数分量顺序不是 [w,x,y,z]（静止时第一项 ≈1，可能性低）。

### 排查需要的信息
- 终端 B 转向那一步的结果行：`✗ 转向超时（只转了 0°）` → 原因 1/2；`只转了 -xxx°` → 原因 3；`✓ 转了 90°` → 读数不准。
- PC2 上 `grep -c quat_to_yaw ~/lhm/A2-dog/body/robot.py`（2 = 新代码）。
- 只读验证：狗趴着时用手（或遥控器）让它原地转一点，PC2 上只读采样观察 quaternion / yaw 的变化。

### 计划的加固（排查后一起做）
- 转向超时收紧到 预计时间 × 1.3 + 1s，即使读数失效也不会大幅过转。
- 转向开始后若 1s 内 yaw 完全无变化 → 立即停止并报错"朝向读数不更新"，而不是一直转到超时。
- 备选：用 `yaw_speed` 或陀螺仪 z 轴积分作为第二来源互相校验。
