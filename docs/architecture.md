## 设计原则

1. **理解上云**：听懂话（ASR + 大模型）、看懂画面（多模态视觉模型）都调用云端（阿里云百炼 / 通义）。
2. **安全留在本地**：急停、看门狗、走多远/转多少的闭环、每次移动的距离上限，全部在 PC2 上，不依赖网络和云端。
3. **本地零推理**：PC2 只多做"视频转发"（不解码、不推理）；服务器只做视频解码和截帧（CPU 足够）。
4. **慢而稳**：视觉相关行为采用"看一眼、走一小步"的低频循环，每一步移动都很短，云端或网络中断时狗最多走完当前一小段就停。

### 为什么这样分
- **PC2 不能上外网**，所以所有云端调用（含看图）只能由服务器发起 → 依赖云端的"组合行为"放在服务器。
- **基础动作和安全放在 PC2**：贴着运控和里程计，网络断了也能自己停。
- **视频不让服务器直接收组播**：实测 WiFi 下组播几乎全丢（3 秒只收到 31 个包，约 0.1 Mbps），必须由 PC2 收组播再单播转发。

### 网络
当前：服务器通过 WiFi `A2-Lab` 直接在狗的 123 网段（服务器 192.168.123.215，PC2 192.168.123.162，PC1 192.168.123.161）。
brain 连接地址是可选项：`--host 192.168.123.162`，或 `brain/config.py` 的 `NETWORKS` 里加一项后用 `--net`（待把 `wifi` 设为默认）。
共享网络建议两端设置相同的 `A2_TOKEN`（握手校验，见 common/protocol.py）。

## 技能分两层

| 层 | 位置 | 工具 | 特点 |
|---|---|---|---|
| 基础动作 | PC2 `body/skills.py` | stand_up、lie_down、stop、move、turn、speak、wait；（阶段3）go_to | 本地闭环、有看门狗、单次移动有上限 |
| 组合行为 | 服务器（阶段2/3 新增） | look、find、approach | 截帧 → 云端看图 → 决策 → 调用基础动作；可随时取消 |

大模型看到的是两层合起来的一张工具表（约 11 个），它不关心工具在哪执行。

## 工具集

| 工具 | 阶段 | 参数 | 实现 |
|---|---|---|---|
| stand_up | 1 | – | StandUp → 等待 → BalanceStand |
| lie_down | 1 | – | StopMove → StandDown |
| stop | 1 | – | StopMove（同时打断正在执行的工具） |
| move | 1 | direction、distance_m(0.1~5)、gait(walk/run) | Move + 里程计闭环；趴着时自动先站起 |
| turn | 1 | direction、angle_deg(5~720) | Move(0,0,wz) + yaw 闭环（yaw 由四元数计算，⚠ 见 known_issues I1） |
| speak | 1 | text(≤30字) | AudioClient.TtsMaker |
| wait | 1 | seconds(0.5~30) | sleep |
| look | 2 | question | 截一帧 → 云端多模态模型回答（"前面有什么""有没有人"），结果显示在大屏 |
| find | **2** | description | 看一眼；没找到就原地转 45° 再看，转满一圈仍未找到则报告；找到后转向对准目标（只原地转） |
| go_to | 2~3 | place | 调用自带 SLAM 导航到标定好的地点（接口待确认，进展快则阶段 2 演示） |
| approach | 3 | description、stop_ratio | 云端识别 + 跟踪器补帧，边走边修正方向；目标框足够大即到达 |
| report | 3 | – | 把本次看到的内容用一句话总结并说出来（"门口有一个穿红衣服、戴眼镜的男生"） |

**狗全程说话**：组合行为在关键节点自动调用 speak（收到指令、到达、找到目标、到达目标、失败原因），不需要大模型每次显式规划。

速度上限（body/skills.py `MotionConfig`，保守值，实测后调）：走 0.4 m/s，跑 0.8 m/s，横移 0.25，后退 0.3，转向 0.6 rad/s。
"跑"目前只是更高的速度上限，没有切换步态（SwitchGait 在 A2 上的含义未确认）。

## "看一眼、走一小步"（approach）

```
loop（每轮约 2~4 秒）:
  截一帧 → 云端："画面里有没有<描述>？给出目标框"
  ├─ 没看到 → 原地转 45°（最多一圈）→ 继续
  ├─ 框高 ≥ stop_ratio × 画面高 → 到达，停止
  └─ 看到了 → 按框的水平偏移先转正 → 按框大小前进一小段（远 1.0m / 近 0.3m）→ 继续
超时 / 连续多次看丢 / 用户取消 → 停止并报告
```

- 本地几乎不耗算力；纯"一步一停"约 20~40 秒走到人身边。
- 每一步都是有上限的基础动作，云端或网络中断时最多走完当前一小段。
- 相机没有深度，距离由目标框高度估计。
- **阶段 3 升级**：服务器上加轻量跟踪器（OpenCV CSRT/KCF，640×360，CPU 即可），云端每 1~2s 给一次目标框校正，
  中间由跟踪器持续跟随，狗可以边走边修正方向，不再一步一停；跟踪器丢失目标时退回"看一眼、走一小步"。

## 一条指令的生命周期

1. 回车开始录音；能量 VAD 检测说完（静音 0.8s）或再按回车结束。
2. `qwen3-asr-flash` 识别（~0.5s）。
3. 命中急停词（停/别动/站住/不要动）→ **不等大模型**，立刻取消当前任务并 `stop`。
   只是短句就结束；长句（如"停下然后趴下"）继续交给大模型。
4. 其他指令：取消正在进行的任务（新指令优先），调用 `qwen3.5-flash` 一次性规划出全部步骤（~1.2s）。
5. executor 逐步执行；基础动作 `call` 给 body，组合行为在服务器本地执行（内部再调用 body）。某步失败则中止后续。
6. body 执行基础动作：Move 以 10Hz 下发，按里程计判断走够距离/转够角度，最后 0.3m / 20° 减速，结束必 StopMove。

例：「门外有人，穿红衣服」→ `go_to(门口) → find(穿红衣服的人) → approach(穿红衣服的人) → lie_down`

## 安全机制

| 场景 | 处理 | 测试 |
|---|---|---|
| 说"停/别动" | brain 跳过大模型，立即 cancel + stop | mock 已测 |
| 新指令打断旧指令 | 取消旧任务 → body 打断并 StopMove → 执行新计划 | mock 已测 |
| brain 进程崩溃/被杀 | TCP 断开 → body 立即 StopMove | mock 已测 |
| 网络卡死但连接没断 | 1s 收不到心跳 → body 看门狗 StopMove | mock 已测（冻结 brain 进程） |
| body 被 Ctrl-C / kill | 退出前打断当前动作并 StopMove | mock 已测 |
| 参数离谱（走 100 米） | tools.sanitize 两端都夹到上限 | – |
| 移动被挡住 | 超过预计时间 2 倍 + 3s → 报超时并停 | – |
| 云端看图慢/失败（阶段2/3） | 组合行为只在"看完"之后才发下一小步动作；看图失败 → 停止并报告 | 待实现 |
| 终极急停 | 遥控器；`/damp`（电机阻尼，狗会软倒） | – |
