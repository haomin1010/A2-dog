## R1 本地算力不足 — 🟢 设计上规避

**记录**：2026-11-20；**更新**：2026-11-22 整体方案改为视觉上云。

### 事实
- PC2：i7-1355U（2 性能核 + 8 能效核，12 线程），只有核显 Iris Xe，**没有任何 AI 加速卡 / 独显 / NPU**（已核对全部 PCIe/USB 设备）。
- 服务器：同样**没有 GPU**。整个系统唯一的"大算力"是云端（通义）。
- PC2 已常驻自带 SLAM（约 0.5 核）、实时内核；不能上外网。

### 处理
- 废弃"PC2 本地跑 YOLO + CLIP"的旧方案。
- 新方案（见 architecture.md）：看图交给云端多模态模型，由服务器调用；PC2 只转发视频（不解码、不推理）；
  跟随采用"看一眼、走一小步"的低频循环，不需要本地高帧率检测。
- 本地 CPU 实测（YOLO/CLIP 测速）不再是前置条件，仅在将来想加本地跟踪器时再做。

### 保留的备选（如果云端方案不行）
| 档位 | 做法 | 代价 |
|---|---|---|
| A | PC2 CPU 跑 YOLOv8n + 上半身颜色统计（CLIP 可选） | 需实测帧率；占 PC2 CPU |
| B | OpenVINO 跑核显 | 需离线安装包 |
| D | 加硬件（Hailo 加速模块 / Jetson） | 采购、确认接口 |

## R2 依赖两段网络 — 🟡

狗 ↔ 服务器走 WiFi，服务器 ↔ 云端走外网，任一段断了，看图类行为就无法继续。
- 缓解：急停、看门狗、移动闭环全在 PC2；组合行为每一步只发有上限的短距离动作，看完才走下一步；看图失败即停止并报告。
- 断网时基础指令仍需要 ASR + 大模型（云端），**断网 = 不能下新指令**，但狗会停在安全状态。
- 可选增强：本地离线急停词监听（借鉴 PC2 `~/audio_test` 的 Vosk + grammar 方案），断网也能喊停。

## R3 云端视觉能力未实测 — 🔴

需要实测的问题（阶段 2，用静态画面，不动狗）：
- 用哪个型号（通义多模态系列，候选在百炼控制台/模型列表里确认）；能否稳定输出**目标框坐标**。
- 单帧延迟（直接决定"看一步走一步"每轮多慢）。
- 准确率：广角、低机位、暗角、逆光下认"穿红衣服的人"是否可靠；多人时能否区分。
- 若不能给框：退而求其次让它回答"偏左/居中/偏右、远/中/近"。

## R4 云端调用费用 — 🔴

每看一帧调用一次多模态接口；一次完整任务预计看 10~30 帧。阶段 2 实测单次费用，必要时降低分辨率 / 减少调用频率。

## R5 隐私 — 🟡

画面中的人会被上传到云端。实验室内需告知相关人员；不保存画面，或只在调试时保存并定期清理。

## R6 自带 SLAM 导航接口未知 — 🔴

已知：指令走 `/api/slam_operate/request`，状态在 `/slam_info`；不知道建图/定位/导航的 api_id 和参数，以及导航是"沿拓扑走到节点"还是"任意坐标规划"。
获取方式：宇树文档中心原文；或现场用 App 走一遍建图→打点→导航，同时录指令。详见 system_notes §4。

## R7 WiFi 抖动导致看门狗误停 — 🟡

看门狗 1s 收不到心跳就停车。WiFi 实测延迟 4~70ms，偶发抖动不会触发，但信号差、连续丢包时狗会走到一半自己停下（日志："没收到心跳"）。
- 真机测试时观察是否出现；如频繁出现，考虑把超时放宽到 1.5~2s（以安全为代价），或改善 WiFi 覆盖。
