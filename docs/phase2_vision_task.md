# 阶段二 A 线：视觉理解模块（任务说明）

> 负责人：学弟（学习向）。不需要碰真机，不依赖 B 线进度。
> 目标：让机器狗"看得懂"——给一张狗相机的画面，能回答问题、能找出"穿红衣服的人"这类目标的位置。

## 1. 背景

- 狗和服务器都没有 GPU，所以看图交给**阿里云百炼的多模态大模型**（和语音、规划用同一个 API key）。
- 你的成果是 `brain/vision.py` 里的两个函数，B 线的"原地找人"和演示大屏会直接调用它们。
- 相机特点：1280×720 广角，**安装位置很低**（大概在人的膝盖高度），画面边缘有暗角，室内偏暗。人经常只露出腿或下半身。

## 2. 接口（不要改签名）

```python
look(image, question) -> LookResult          # 回答问题；LookResult.answer / .targets / .latency
locate(image, description) -> list[Target]   # 找目标；Target.box = [x1,y1,x2,y2]，0~1 归一化
```

`image` 是 OpenCV 的 BGR 数组。现在的实现是一个能跑但很粗糙的基线（qwen3.5-flash + 简单提示词），你要在接口不变的前提下把它做好。

## 3. 任务

### 3.1 建测试集（第 1 周）
- 截图：`python tools/capture_frames.py --every 2 --count 50`（需要在服务器上、狗开机时运行；也可以让 B 线帮你截好）。
- 场景要多样：0 / 1 / 多个人；不同衣服颜色；远近不同；只露出腿；背光；有人戴眼镜 / 拿东西。
- 标注：每张图记录人数、每个人的框和衣服颜色、2~3 个问题和标准答案。格式自定，建议一张图一个 JSON，或用 labelme 之类的工具标框。

### 3.2 对比模型（第 1~2 周）
候选（实测可用）：`qwen3.5-flash`、`qwen3.5-plus`、`qwen3-vl-plus`，可再试 `qwen3.5-omni-flash`。

对每个模型统计：

| 指标 | 说明 |
|---|---|
| 计数准确率 | "有几个人"答对的比例 |
| 定位准确率 | 预测框和标注框 IoU ≥ 0.5 算找对；统计召回率、误报率 |
| 描述匹配 | locate("穿红衣服的人") 是否找对了那个人、有没有找错人 |
| 延迟 | 每次调用的平均 / 最慢耗时 |
| 费用 | 每次调用的 token 数 × 单价（百炼控制台查价格） |
| 格式稳定性 | 输出能被解析成合法 JSON 的比例 |

### 3.3 优化（第 2~3 周）
- 提示词：怎么写能让输出格式稳定、框更准、少误报。
- 上传分辨率：`SEND_WIDTH` 取 640 / 960 / 1280 对准确率和延迟的影响。
- 失败兜底：解析失败时重试一次？还是返回空？
- 开放描述：除了颜色，试试"戴眼镜的人""手里拿东西的人""坐着的人"。

### 3.4 交付
1. 改进后的 `brain/vision.py`（接口不变）。
2. 一份评测报告（表格 + 结论）：**推荐哪个模型、什么参数，延迟和单次费用是多少，哪些情况容易错**。
3. 评测脚本（例如 `tools/eval_vision.py`），以后换模型能一键重跑。

## 4. 已知的初步结果（B 线冒烟测试，1 张图，2026-11-24）

## 6. 学习要点

- 多模态大模型的调用方式（图片怎么传、token 怎么算）。
- 提示词工程：怎么让模型稳定输出结构化结果。
- 目标检测的评测方法：IoU、召回率、误报率。
- 工程权衡：准确率、延迟、费用三者怎么取舍。
